# MICRODUCK 动态买入反弹比例设计

## 目标

买入价格跌得越深时，允许更大的反弹幅度，减少短暂小反弹导致过早买入的情况。同时设置明确上限，避免反弹门槛无限增大。

## 适用范围

- 仅在 `buy_trailing_rebound_mode` 为 `percentage` 时启用动态反弹比例。
- 固定金额反弹模式保持现有行为，不使用动态比例。
- 本次不修改卖出跟踪和回落规则。

## 配置

保留现有基础反弹比例字段，并新增两个可在部署时确认、运行中安全修改的字段：

- `buy_trailing_rebound_percent`：基础反弹比例，默认 `5`，表示 5%。
- `buy_trailing_rebound_adjustment_factor`：跌幅调整系数，默认 `0.5`。
- `buy_trailing_rebound_max_percent`：最大反弹比例，默认 `10`，表示 10%。

约束：

- 基础反弹比例必须大于 0 且小于 100。
- 调整系数必须大于等于 0。
- 最大反弹比例必须大于等于基础反弹比例且小于 100。
- 配置更新只影响后续价格判断，不重置已经记录的最低价。

## 计算规则

进入买入跟踪状态后，以配置的买入触发价和持续刷新的最低价计算相对跌幅：

```text
相对跌幅 = max(0, (买入触发价 - 最低价) / 买入触发价)
实际反弹比例 = min(最大反弹比例, 基础反弹比例 + 相对跌幅 × 调整系数 × 100)
动态买入价 = 最低价 × (1 + 实际反弹比例 / 100)
```

其中基础比例和最大比例以百分数配置，计算时转换为比例。最低价每次刷新后，实际反弹比例和动态买入价都必须重新计算。

示例：买入触发价为 0.013 美元，最低价为 0.0104 美元，相对跌幅为 20%。基础比例为 5%，调整系数为 0.5，计算比例为 15%，受上限约束后实际使用 10%，动态买入价为 0.01144 美元。

当最低价高于买入触发价时，相对跌幅按 0 计算，实际反弹比例使用基础比例，不允许出现负调整。

## 运行行为

每次取得新的有效买入报价后：

1. 如果报价刷新了最低价，则先更新最低价。
2. 根据最新最低价重新计算相对跌幅、实际反弹比例和动态买入价。
3. 当前可成交买入价达到动态买入价，并且继续满足现有买入上限、价格复核和交易安全条件时，才允许提交买入。
4. 任何报价、余额或路由异常仍按现有安全策略跳过本轮，不改变最低价和交易状态。

## 界面与日志

部署独立配置和运行中安全配置均显示：

- 买入基础反弹比例
- 买入反弹调整系数
- 最大买入反弹比例

字段使用中文名称，问号说明中展示原字段名、计算方式和单位。

买入跟踪日志显示：当前可成交价、最低价、相对跌幅、基础比例、实际比例和动态买入价。达到上限时直接显示最终实际比例，不产生容易误解的额外状态。

## 兼容性

- 未配置新增字段的旧模板和旧独立配置自动使用调整系数 `0.5`、最大比例 `10`。
- 现有基础比例不被强制改写；新建配置默认使用 `5`。
- 固定金额模式继续只读取固定反弹金额。
- 状态恢复后沿用已保存的最低价，并按当前配置重新计算动态买入价。

## 验证

后端测试覆盖：

- 未下跌时使用 5% 基础比例。
- 下跌后按公式提高实际比例。
- 计算结果超过 10% 时使用 10%。
- 最低价刷新后动态买入价重新计算。
- 固定金额模式不受影响。
- 非法配置被拒绝。
- 运行中修改安全字段后不重置最低价。

前端测试覆盖新增字段的中文名称、默认值、说明和部署数据提交。最后构建镜像并在没有真实交易的情况下验证配置展示和计算日志。
