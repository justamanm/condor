# DEX 搜索与 Uniswap v4 池 ID 修复设计

## 问题

Condor 当前把 GeckoTerminal 的搜索限制为代币地址，名称和代币符号不会发出查询。页面还会把所有合法代币地址同时当作资金池地址查询，因此搜索合约地址时会出现一个无意义的 404。

Robinhood Chain 上的部分 Uniswap v4 资金池使用 32 字节池 ID，形式为 `0x` 加 64 个十六进制字符。Condor 当前只允许普通的 20 字节 EVM 地址，因此这些真实资金池能够出现在列表中，却无法打开详情。

## 修复范围

1. DEX 搜索接受名称、代币符号和代币合约地址。
2. 名称或符号通过 GeckoTerminal 的通用池搜索查询，并只保留当前网络的结果。
3. 代币合约地址继续使用按代币查询接口，避免降低结果准确度。
4. 普通池地址和 Uniswap v4 的 32 字节池 ID 可以直接查询详情。
5. 只有符合池地址形式的输入才并行查询池详情；代币合约地址查询池详情得到 404 时，不在页面显示为错误。
6. 保留前端 400 毫秒等待和后端缓存，避免逐字请求及过度消耗 GeckoTerminal 的请求额度。

## 页面行为

- 输入 `microduck` 或 `MICRODUCK`：显示当前网络中的相关资金池。
- 输入 MICRODUCK 合约地址：显示该代币的资金池，不显示误导性的 404。
- 输入普通池地址：显示可直接打开的资金池。
- 输入 Uniswap v4 池 ID：可以打开详情页并读取数据。
- 上游限流或故障：保留现有提示，不伪装成“没有资金池”。

## 测试

- 后端测试名称、符号、代币地址、普通池地址和 v4 池 ID。
- 前端测试输入判断以及正确的请求方式。
- 运行后端相关测试、前端构建，并在已登录的 Condor 页面实际搜索和打开 MICRODUCK 池。

## 改动控制

优先复用现有搜索、缓存和限流代码。预计修改量以新增判断和测试为主，不删除重要文件，不改变交易策略、钱包或机器人运行状态。
