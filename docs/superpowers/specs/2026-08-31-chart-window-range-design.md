# 图表 Window 可见范围修复设计

## 问题

DEX 图表切换 `1h`、`6h`、`1d`、`3d` 等 Window 后，按钮状态会改变，也会按新时长请求历史数据，但图表仍可能显示之前 Window 的全部缓存数据。

原因是不同 Window 共用同一个行情缓存。切换时只向后端发送新的时长提示，没有重新设置图表横轴的可见起止时间；现有“显示全部数据”又只在首次加载执行。

## 方案比较

1. 把 Window 加入缓存标识：实现简单，但每次切换都会建立新缓存和新的实时订阅，浪费请求额度。
2. 切换时删除范围外的缓存：当前范围会正确，但切回更长范围时必须重新下载数据。
3. 保留完整缓存，只调整图表可见范围：既能立即切换，也不会增加订阅和重复请求。本次采用此方案。

## 预期行为

- 点击 Window 后，图表横轴显示“当前时间减去所选时长”到“当前时间”。
- `1d` 只显示最近24小时，`3d` 只显示最近72小时，其他选项同理。
- 如果范围内没有成交，图表可以为空白或只显示少量K线，不能继续展示范围外的旧K线。
- 切回更长 Window 时复用缓存中的历史数据。
- 实时K线更新不能反复重置用户的手动缩放。
- 切换交易对、K线间隔或资金池时，对新图表应用当前选中的 Window。

## 实现边界

- 新增一个纯函数，根据当前时间和 Window 秒数计算横轴范围，便于独立测试。
- `TradeChart` 仅在 Window、交易对、K线间隔或资金池发生变化时应用范围。
- 不修改后端行情接口、缓存结构、WebSocket订阅、交易策略或机器人。

## 测试

- 单元测试验证 `1d`、`3d` 的起止时间和毫秒时间归一化。
- 前端类型检查与构建通过。
- 在真实 DEX 页面切换 `1d` 和 `3d`，读取图表横轴可见范围，确认宽度分别约为24小时和72小时。

## 改动控制

预计新增一个小型纯函数和一段图表同步逻辑，不删除历史缓存，不新增依赖，不删除重要文件。
