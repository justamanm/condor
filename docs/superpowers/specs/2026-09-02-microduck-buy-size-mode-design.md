# MICRODUCK 买入方式设计

## 目标

部署 MICRODUCK Bot 时，用户可以二选一：固定美元预算买入，或固定 MICRODUCK 数量买入。界面提供按当前价格换算的参考值，真实下单仍使用下单前的最新可成交报价和价格保护。

## 配置字段

- `buy_size_mode`：买入方式，允许 `budget` 或 `quantity`。
- `buy_budget_usd`：预算模式下最多投入的美元金额。
- `buy_amount_base`：数量模式下要求买入的 MICRODUCK 数量。

模板保留两个数值字段，但每次部署只能启用其中一个。生成独立配置时保存买入方式及两个数值，策略只读取当前方式对应的数值。旧配置没有 `buy_size_mode` 时默认使用 `budget`，保持原有行为。

## 部署界面

“买入方式”使用下拉框，选项为“按预算”和“按数量”。

- 按预算：显示美元预算输入框，后方提供换算按钮；点击后使用当前价格显示预计 MICRODUCK 数量。
- 按数量：显示 MICRODUCK 数量输入框，后方提供换算按钮；点击后使用当前价格显示预计美元金额。
- 换算结果是参考值，不自动改变另一个配置字段。
- 当前价格不可用时，按钮不可执行并明确显示“暂未取得当前价格”。
- 用户必须确认当前选中的方式和值，才能部署独立配置。

## 报价和下单

### 预算模式

在触发买入时，根据最新可成交单价将预算换算为目标数量，再请求最终报价。实际允许支出不得超过预算；超过时取消本轮买入并继续跟踪。

### 数量模式

直接使用 `buy_amount_base` 请求 BUY 报价。报价必须是精确数量模式，并返回最大投入金额；如果 Gateway 标记为近似报价，或不支持精确输出，则取消本轮买入，不改成近似数量交易。

下单前再次检查：

1. 最新价格仍满足买入触发条件。
2. 最终单位价格不超过买入价格上限。
3. 最大投入金额与最终单位价格一致且为有效正数。
4. 数量模式的报价不是近似结果。

执行时使用已确认的报价或等价的精确数量参数，并保留滑点带来的最大投入保护。

## 状态与日志

- 启动日志显示“买入方式=按预算/按数量”及对应配置值。
- 买入确认日志同时显示目标数量、预计投入和最大允许投入。
- 数量模式无法精确成交时，日志明确写明“当前路由不支持精确数量买入，本轮取消”，不得记录为成交失败或重复重试交易。
- 页面中的 Bot 配置区域显示实际采用的买入方式和值。

## 运行中修改

`buy_size_mode`、`buy_budget_usd` 和 `buy_amount_base` 都属于可安全更新字段，但只允许在等待买入或买入跟踪阶段修改。已持仓、卖出跟踪或交易确认中拒绝修改，避免改变已建立持仓的交易含义。

## 测试

- 旧配置缺少新字段时仍按预算模式运行。
- 预算模式按预算计算数量，并拒绝超过预算的最终报价。
- 数量模式使用固定数量，并拒绝近似报价。
- 两种模式的部署表单、独立配置内容和启动日志一致。
- 当前价格不可用、输入为零或负数时不能换算或部署。
- 运行中的安全更新只在未持仓阶段生效。

## 改动评估

本次以新增代码为主：增加两个配置字段、部署表单的选择和换算、策略分支及测试。不会删除现有预算逻辑；旧配置继续兼容。为避免两套下单流程重复，最终报价校验和提交交易应共用现有函数，只在目标数量的来源及精确报价检查处增加分支。
